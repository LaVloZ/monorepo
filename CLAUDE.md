# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Nature of this repo

A container that gathers former standalone repos into one place. The monorepo itself imposes **no technology, no tooling and no conventions** on its content: any kind of project, in any language or stack, can live here.

- **Each top-level directory is an independent project.** There is no root build, no shared dependencies, no workspace tooling, and projects don't depend on each other.
- Treat each project as if it were its own repo: `cd` into it, and follow its own `README.md`, build files and conventions (language version, build tool, test framework, style).
- The root `README.md` is the index of the projects it contains; keep it up to date when adding or removing one.
- Don't assume a convention seen in one project applies to another, and don't introduce cross-project sharing or root-level tooling unless asked.

## Working on a project

To find how to build, run or test a project, look inside it: its `README.md` first, then its build/config files (`pom.xml`, `build.gradle`, `package.json`, `CMakeLists.txt`, `Makefile`, etc.). Prefer the project's wrapper or scripts when it has them. A project may itself contain its own `CLAUDE.md` with more specific guidance.

## Git history conventions

- `main` has one merge commit per imported repo (`git log --first-parent`).
- Each imported repo's history was rewritten with `git filter-repo --to-subdirectory-filter`, so `git log` / `git blame` work per file inside each folder.
- Non-default branches of the original repos are kept as `<folder>/<branch>`.
- Code was imported unchanged; don't "modernize" a project unless asked.

## Tooling

`.nwave/` is generated by the nWave plugin and git-ignored; don't edit it.
